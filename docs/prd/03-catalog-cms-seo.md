# PRD-03 — کاتالوگ، CMS و SEO

## هدف
معرفی قابل اعتماد محصولات اختصاصی، خدمات تزریق و مواد پلیمری و انتشار مقالات تخصصی فارسی، با کنترل کامل روی صحت ادعاها و انتشار عمومی.

## نیازمندی‌های کاتالوگ

### FR-01: محصولات، خدمات و مواد
هر آیتم عمومی باید حداقل عنوان، slug یکتا، توضیح، رسانه مجاز، وضعیت انتشار و metadata لازم را داشته باشد. مشخصات فنی فقط پس از تأیید کسب‌وکار منتشر می‌شوند.
- **سناریو:** بازدیدکننده صفحه یک محصول منتشرشده را باز می‌کند.
- **پذیرش:** فقط رکورد منتشرشده نمایش داده می‌شود؛ draft و رکورد غیرفعال از API عمومی قابل دریافت نیست.

### FR-02: دسته‌بندی و مسیرهای جزئیات
فهرست‌ها باید صفحه‌بندی و مسیرهای قابل اشتراک‌گذاری داشته باشند؛ slug تکراری یا تغییر مسیر بدون مدیریت redirect پذیرفته نیست.
- **سناریو:** کاربر دسته مواد پلیمری را انتخاب می‌کند.
- **پذیرش:** فهرست مرتبط، حالت خالی و navigation معتبر است.

### FR-03: Strapi CMS
مقاله‌ها، دسته‌ها و برچسب‌ها از Strapi v5 مدیریت شوند. نقش عمومی فقط دسترسی خواندن محتوای منتشرشده داشته باشد.
- **سناریو:** درخواست ناشناس برای ایجاد، ویرایش یا حذف مقاله ارسال می‌شود.
- **پذیرش:** درخواست رد می‌شود؛ خواندن draft نیز از دسترس عمومی خارج است.

### FR-04: گردش انتشار محتوا
مقاله جدید به‌طور پیش‌فرض draft باشد. انتشار عمومی نیازمند اقدام صریح کاربر مجاز و بازبینی محتوا است. ابزار MCP نباید بدون درخواست صریح، محتوا را منتشر یا حذف کند.
- **سناریو:** ایجنت MCP مقاله جدیدی ایجاد می‌کند اما پارامتر انتشار تعیین نشده است.
- **پذیرش:** مقاله draft باقی می‌ماند و هیچ صفحه عمومی یا sitemap آن را نمایش نمی‌دهد.

### FR-05: SEO فنی
صفحات عمومی باید title، meta description، canonical، Open Graph، sitemap و robots مناسب داشته باشند. JSON-LD فقط از داده تأییدشده ساخته شود.
- **سناریو:** مقاله منتشرشده در CMS و صفحه عمومی در دسترس است.
- **پذیرش:** صفحه canonical صحیح دارد، در sitemap قرار می‌گیرد و metadata با محتوای واقعی سازگار است.

### FR-06: بازاعتباردهی کش
وب‌هوک CMS با secret معتبر فقط مسیرهای مرتبط را revalidate کند.
- **سناریو:** وب‌هوک بدون secret یا با secret اشتباه فراخوانی می‌شود.
- **پذیرش:** درخواست رد می‌شود و cache محتوای خصوصی یا نامرتبط پاک/منتشر نمی‌شود.

## امنیت و محتوا
- هیچ کلید مدیریتی Strapi در فرانت‌اند یا ابزار MCP قابل مشاهده عمومی قرار نگیرد.
- URL تصاویر و مقالات از متغیر محیطی دامنه عمومی ساخته شود؛ localhost فقط در توسعه.
- ورودی MCP شامل طول فیلد، slug، شناسه، صفحه‌بندی و وضعیت مجاز اعتبارسنجی شود.
- حذف محتوا باید محافظت‌شده و قابل تأیید باشد؛ ترجیح با unpublish/archive است.
- هیچ ادعای تأییدنشده درباره ظرفیت، قیمت، گواهی یا زمان تحویل منتشر نشود.

## معیار پذیرش
- تست anonymous read-only در Strapi.
- تست draft/published و sitemap.
- تست webhook معتبر/نامعتبر.
- تست SEO metadata برای صفحه محصول، دسته و مقاله.
- تست MCP برای پیش‌فرض draft، اعتبارسنجی ورودی و منع حذف/انتشار ناخواسته.
