# PRD-07 — سخت‌سازی آمادگی تولید

## وضعیت
**اولویت فوری — نیازمند اصلاح و راستی‌آزمایی مجدد.** این سند بر مبنای ممیزی read-only مخزن در 2026-10-28 تهیه شده است. موارد زیر باید روی شاخه فعلی دوباره بررسی شوند؛ این سند به‌تنهایی اثبات نمی‌کند که آسیب‌پذیری در محیط زنده exploit شده است.

## HR-01: مجوز عمومی Strapi فقط خواندنی (P0)
**مشاهده ممیزی:** `cms/src/index.ts` نقش عمومی را با مجوزهای create/update/delete مقاله پیکربندی می‌کند.
- **نیازمندی:** نقش Public فقط مجوزهای خواندن محتوای منتشرشده را داشته باشد.
- **سناریو:** درخواست ناشناس POST/PUT/DELETE به endpoint مقاله می‌فرستد.
- **پذیرش:** همه عملیات نوشتن رد می‌شوند؛ draft از API عمومی قابل خواندن نیست.
- **راستی‌آزمایی:** تست integration برای درخواست ناشناس و بررسی تنظیمات role پس از bootstrap.

## HR-02: حذف رمز پیش‌فرض مدیر Strapi (P0)
**مشاهده ممیزی:** در bootstrap مقدار fallback قابل حدس `Toranj@Admin2026` و ایمیل ثابت مدیر وجود دارد.
- **نیازمندی:** در production نبود `BOOTSTRAP_ADMIN_PASSWORD` یا secret لازم باید باعث توقف امن bootstrap شود؛ رمز پیش‌فرض شناخته‌شده ممنوع است.
- **سناریو:** متغیر رمز مدیر در production تنظیم نشده است.
- **پذیرش:** هیچ حسابی با رمز پیش‌فرض ساخته نمی‌شود؛ secret در log یا خروجی API دیده نمی‌شود.
- **نکته:** ایجاد حساب مدیر باید با رویه امن و مستند انجام شود.

## HR-03: رفع خطای CI مدیریت Promise (P0)
**مشاهده ممیزی:** اجرای اخیر `pnpm check` در `backend/src/quotations/quotations.service.ts` حوالی خطوط 446–451 به دلیل `no-floating-promises` شکست خورده است.
- **نیازمندی:** رفتار asynchronous به‌درستی await/catch یا به‌صورت آگاهانه مدیریت شود.
- **سناریو:** خطای عملیات asynchronous رخ می‌دهد.
- **پذیرش:** خطا گم نمی‌شود؛ تست رفتار موفق و شکست اضافه می‌شود؛ `pnpm check` سبز می‌شود.

## HR-04: یکسان‌سازی متغیرهای ذخیره‌سازی رسانه (P0)
**مشاهده ممیزی:** config بک‌اند `MEDIA_ROOT` می‌خواند، در حالی که Compose `MEDIA_STORAGE_ROOT` تنظیم می‌کند.
- **نیازمندی:** نام متغیر در config، Compose، Dockerfile، runbook و env example یکسان شود یا mapping صریح و تست‌شده وجود داشته باشد.
- **سناریو:** سرویس با NODE_ENV=production و volume رسانه اجرا می‌شود.
- **پذیرش:** سرویس بالا می‌آید و فایل‌ها در مسیر volume پایدار نوشته/خوانده می‌شوند.

## HR-05: تنظیم origin واقعی فرانت‌اند (P1)
**مشاهده ممیزی:** backend مقدار `FRONTEND_ORIGIN` را می‌خواند و در صورت نبود، به localhost:3000 برمی‌گردد.
- **نیازمندی:** origin محیط production صریحاً تنظیم و با CORS/redirect policy هماهنگ شود.
- **سناریو:** مرورگر از دامنه واقعی فرانت‌اند به API درخواست می‌فرستد.
- **پذیرش:** origin معتبر پذیرفته و origin غیرمجاز رد می‌شود؛ مقدار localhost در production استفاده نمی‌شود.

## HR-06: پیاده‌سازی واقعی درگاه پیامک (P1)
**مشاهده ممیزی:** `HttpSmsProvider.send` صرفاً log می‌کند و پاسخ موفق مصنوعی برمی‌گرداند.
- **نیازمندی:** درخواست واقعی به provider پیکربندی‌شده ارسال شود؛ timeout، خطا، پاسخ نامعتبر و retry مدیریت شوند.
- **سناریو:** provider پیامک خطا می‌دهد یا timeout می‌شود.
- **پذیرش:** سیستم موفقیت کاذب گزارش نمی‌کند؛ شناسه پیام فقط از پاسخ معتبر provider ثبت می‌شود؛ secretها در log نیستند.
- **نکته:** حالت mock باید فقط برای توسعه/تست قابل استفاده باشد و در production fail-fast یا هشدار بحرانی بدهد.

## HR-07: پیش‌فرض امن برای ابزار MCP (P1)
**مشاهده ممیزی:** ابزار MCP ایجاد مقاله را به‌طور پیش‌فرض published می‌کند، امکان حذف مقاله دارد و URL عمومی localhost را hardcode کرده است.
- **نیازمندی:** وضعیت پیش‌فرض draft، انتشار با اقدام صریح، حذف با تأیید صریح/ترجیحاً unpublish یا archive، URL مبتنی بر `PUBLIC_SITE_URL`.
- **سناریو:** ایجنت بدون پارامتر status مقاله می‌سازد.
- **پذیرش:** مقاله draft است؛ URL در دامنه پیکربندی‌شده ساخته می‌شود؛ حذف ناخواسته ممکن نیست.

## HR-08: اعتبارسنجی ورودی‌های MCP (P1)
- **نیازمندی:** همه ابزارها schema اعتبارسنجی مشخص برای طول رشته، slug، شناسه، صفحه‌بندی، status و URL داشته باشند.
- **سناریو:** ورودی خارج از محدوده یا status ناشناخته ارسال می‌شود.
- **پذیرش:** درخواست قبل از فراخوانی Strapi رد می‌شود و خطای امن و قابل فهم برمی‌گردد.

## HR-09: پوشش آزمون انتشار و بازگشت (P1)
- **نیازمندی:** پس از رفع موارد فوق، migration روی دیتابیس تمیز، تست‌های integration و E2E مرتبط، smoke test و restore بک‌آپ اجرا شوند.
- **سناریو:** نسخه نامزد انتشار روی محیط staging بالا می‌آید.
- **پذیرش:** تمام گیت‌های CI سبز هستند؛ دسترسی عمومی CMS، ثبت استعلام، پنل مشتری، صدور/دانلود پیش‌فاکتور و مقاله منتشرشده بررسی شده‌اند.
