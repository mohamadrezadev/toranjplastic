# برنامه اجرایی فاز ۲ — سایت عمومی و CMS

تاریخ: ۱۰ اکتبر ۲۰۲۶

## هدف فاز

تبدیل پوسته عمومی فعلی به کاتالوگ و سامانه محتوای قابل مدیریت برای محصول، دسته‌بندی، خدمات تزریق، مواد اولیه، مقاله و صفحات ثابت؛ بدون تبدیل پروژه به فروشگاه و بدون انتشار ادعای تأییدنشده.

## مبنا

- PRD 01: صفحات عمومی، ناوبری، RTL و مسیرهای اصلی
- PRD 03: CMS، lifecycle محتوا، کاتالوگ و SEO
- PRD 02: احراز هویت و الزام کنترل مجوز ادمین در سرور
- Roadmap: فاز ۲ برای سایت عمومی و CMS؛ تکمیل SEO فنی در فاز ۵

## ترتیب اجرایی

### برش ۲.۱ — پایه داده و API عمومی محتوا

- مدل‌های Prisma برای Category، Product، InjectionService، Material، Article و ManagedPage
- وضعیت محتوای `Draft`، `Published` و `Archived`
- slug یکتا، ترتیب، metadata و زمان انتشار
- endpointهای عمومی فقط‌خواندنی برای فهرست و جزئیات محتوای منتشرشده
- عدم نمایش draft/archived و عدم ارائه قیمت، موجودی، ظرفیت یا زمان تحویل تأییدنشده
- migration نام‌دار، تست قرارداد و تست منفی lifecycle

### برش ۲.۲ — صفحات عمومی متصل به محتوا

- فهرست و جزئیات محصولات
- خدمات تزریق و مواد اولیه
- فهرست و جزئیات مقالات
- درباره ما، تماس و صفحات قانونی مدیریت‌شده
- loading/empty/error/404، metadata و breadcrumb
- تست ۳۶۰، ۳۹۰، ۷۶۸ و ۱۲۸۰ در تم روشن و تاریک

### برش ۲.۳ — پیش‌نیاز هویت ادمین

- اجرای حداقل زیرساخت امن هویت و session از PRD 02 پیش از فعال‌شدن endpointهای نوشتن CMS
- نقش Customer به‌صورت پیش‌فرض و اعطای Admin فقط توسط مسیر مجاز سمت سرور
- cookie امن، CSRF متناسب، rate limit و failure test برای دسترسی غیرمجاز
- سرویس OTP نهایی همچنان نیازمند تصمیم عملیاتی است و با مقدار ساختگی جایگزین نمی‌شود

### برش ۲.۴ — عملیات و پنل CMS

- ایجاد، ویرایش، پیش‌نمایش، انتشار و آرشیو محتوا
- جلوگیری از slug تکراری و حذف فیزیکی محتوای وابسته
- مدیریت alt تصاویر و metadata
- پنل خصوصی `noindex` و `no-store`
- کنترل همه مجوزها در backend و ثبت رخدادهای حساس

### برش ۲.۵ — تحویل محتوایی و SEO فاز ۲

- metadata اختصاصی و URL پایدار برای محتوای منتشرشده
- Product، Article و Breadcrumb structured data فقط با داده واقعی
- redirect ثبت‌شده هنگام تغییر slug
- sitemap فقط برای محتوای منتشرشده
- بهینه‌سازی تصویر و alt
- Search Console، پایش نهایی، robots و quality gate انتشار در فاز ۵ تکمیل می‌شوند

## تصمیم وابستگی امنیتی

پنل CMS و endpoint نوشتن تا قبل از برش ۲.۳ عمومی یا بدون محافظ ساخته نمی‌شوند. برش‌های ۲.۱ و ۲.۲ فقط contract خواندن محتوای منتشرشده را فعال می‌کنند. این ترتیب، خروجی عمومی فاز را جلو می‌برد و هم‌زمان قانون قطعی «مجوز ادمین فقط سمت سرور» را حفظ می‌کند.

## قواعد داده

- public API فقط رکورد `Published` با `publishedAt` معتبر را برمی‌گرداند.
- archive بر delete فیزیکی ترجیح دارد.
- slug در حوزه مدل یکتا و پایدار است.
- مقدار تجاری حساس فقط با منبع، تأیید و زمان به‌روزرسانی معتبر اجازه انتشار دارد؛ برش ۲.۱ هیچ فیلد قیمت یا موجودی عمومی ارائه نمی‌کند.
- تصویر بدون منبع و مجوز تأییدشده به‌عنوان محصول واقعی نمایش داده نمی‌شود.
- محتوای seed آزمایشی، در صورت نیاز تست، draft می‌ماند و وارد سایت عمومی نمی‌شود.

## معیار پایان فاز

- مدیر مجاز بتواند همه انواع محتوای PRD 03 را مدیریت کند.
- فقط محتوای منتشرشده در API عمومی، صفحات و sitemap ظاهر شود.
- صفحات عمومی در RTL، هر دو تم و چهار viewport الزامی تست شوند.
- endpointهای خصوصی failure test مجوز داشته باشند.
- migration، rollback/backup note، lint، typecheck، test، build و OpenSpec strict validation پاس شوند.

## شروع فعلی

Change نخست فاز ۲ با عنوان `build-public-content-read-foundation` فقط برش ۲.۱ را اجرا می‌کند. برش‌های بعدی هرکدام Change مستقل و قابل بازبینی خواهند داشت.

## نتیجه برش ۲.۱

- شش خانواده محتوایی و lifecycle مشترک با migration نام‌دار و غیرمخرب به Prisma اضافه شدند.
- API عمومی فقط‌خواندنی برای category، product، injection service، material، article و managed page ایجاد شد.
- فیلتر انتشار مؤثر، شرط انتشار category محصول، pagination محدود، ترتیب قطعی و DTO صریح پیاده شد.
- JSON تصویر و مشخصات قبل از خروج normalize می‌شود و URL/CTA ناامن یا ساختار خام نامعتبر عبور نمی‌کند.
- هیچ endpoint نوشتن، seed عمومی، قیمت، موجودی، ظرفیت، زمان تحویل یا ادعای تجاری اضافه نشد.
- migration روی PostgreSQL 17 خالی اعمال و وضعیت schema تأیید شد؛ collection واقعی خالی و health سالم بودند.
- ۱۸ تست واحد بک‌اند، ۹ تست contract/e2e بک‌اند، ۱۸ تست فرانت و build هر دو workspace پاس شدند.

## نتیجه برش ۲.۲

- صفحات فهرست و جزئیات محصول، خدمت تزریق، ماده اولیه و مقاله به API عمومی محتوای منتشرشده متصل شدند.
- صفحات درباره ما، تماس، حریم خصوصی و شرایط استفاده از managed page خوانده می‌شوند و در نبود محتوای منتشرشده هیچ متن تماس، حقوقی یا ادعای سازمانی ساخته نمی‌شود.
- مرز typed server-side API، اعتبارسنجی پاسخ، metadata تأییدشده، breadcrumb، pagination و حالت‌های مستقل loading، empty، error و 404 پیاده شد.
- صفحات عمومی با Partial Prerendering ساخته می‌شوند؛ build به روشن‌بودن backend وابسته نیست و محتوای runtime پشت loading boundary دریافت می‌شود.
- محتوای فهرست و جزئیات در تم روشن و تاریک و عرض‌های ۳۶۰، ۳۹۰، ۷۶۸ و ۱۲۸۰ بدون overflow افقی آزموده شد.
- fixture قطعی E2E حالت‌های موفق، خالی، خطای upstream و not-found را بدون seed عمومی یا تغییر داده واقعی پوشش می‌دهد.
- مسیرهای `/inquiry` و `/account` تا برش احراز هویت و استعلام همچنان provisional و `noindex` هستند.

## ورودی استقرار و بازگشت برش ۲.۲

- مقدار server-side متغیر `BACKEND_API_URL` باید به ریشه نسخه‌دار backend مانند `https://api.example.com/api/v1` اشاره کند؛ `NEXT_PUBLIC_API_URL` فقط fallback سازگار محیط توسعه است.
- دامنه نهایی media هنوز تصویب نشده است؛ تصاویر normalize‌شده فعلاً با عنصر native و ابعاد/بارگذاری تنبل نمایش داده می‌شوند و پیکربندی بهینه‌سازی host پس از انتخاب media provider انجام می‌شود.
- بازگشت این برش فقط با revert مسیرها، client و componentهای frontend انجام می‌شود؛ migration یا rollback داده ندارد و API عمومی برش ۲.۱ مستقل باقی می‌ماند.

## ادامه فاز

برش بعدی `۲.۳ — پیش‌نیاز هویت امن ادمین` است. عملیات نوشتن CMS، media provider، redirect history، sitemap، structured data، تکمیل SEO و PWA همچنان باز هستند و در Changeهای بعدی انجام می‌شوند.
